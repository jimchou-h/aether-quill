## Context

既有方案为自然语言，含【2. 改写拍点】与【3. 保留清单】；作者可直接编辑。正文单章和长章分段走不同 user prompt，但共用 `chapter.optimize.draft` task prompt。当前运行时提示要求整段可见改写；连续性 review 只看方案和成稿，自检调用失败在 Web 中降级为无缺口。仓库有大量未提交的精修编排改动，本变更限于旧方案改写链，不触碰新入口。

## Goals / Non-Goals

**Goals:** 指定拍点产生可见且符合预期的变化；有效原文和三类保留材料得到保护；验收能指出可定位的未落实或丢失；自检失败状态真实。

**Non-Goals:** 将方案转为严格 JSON、自动逐条定位/替换、按场成稿重构、基于改动率判定文学质量。

## Decisions

1. **保持作者可编辑的自然语言方案。** 不改 plan API 或方案 UI。正文 prompt 明确将【2】作为改动目标、【3】作为保留边界；方案没有这些标题时，按原有用户要求与方案整体意图执行，不拒绝旧方案或自定义方案。
2. **收紧单章与分段正文同一语义。** 仓库默认 task prompt、API 运行时 prompt 与模板治理副本同步更新；取消无条件“每段都要改”的要求。分段仍按既有边界和预算运行，只有属于该段的拍点才要求落地；方案若无法明确定位，模型应按原文与方案尽力判断，不凭空增补事实。项目已发布的自定义 Task Prompt 保持优先，不静默覆盖。
3. **扩展现有连续性 review 的检查目标。** 输入原文、方案、成稿；输出仍为 `CLOSED/GAPS` 加可定位缺口，重点检查改写拍点未落实、有效材料丢失、事实连续性。只报告证据充分的实质问题，禁止提出新润色愿望。复用现有 review SSE 与最多一次补修，不加 API 字段、错误码或调用轮数。
4. **自检失败显式呈现。** 保留首稿并允许作者手动查看和应用；前端显示“自检未完成”，不写“无缺口已收口”，也不自动触发补修。失败分支保留错误信息供重试或人工处理。
5. **验证先行。** 单测覆盖默认 prompt 与单章/分段 prompt 的语义、review 的原文注入和 `GAPS/CLOSED` 解析、前端失败分支。真实模型样章评测按 RAG 质量基线记录；未通过前不宣称质量达标。

## Risks / Trade-offs

- **自然语言方案难以精确解析** → V1 用模型语义验收和原文证据，不把字符串差异当作拍点完成；真实样章核查误判。
- **降低全段改写压力后可能出现偷懒** → 明确指定拍点必须有实质变化，review 对照原文查未落实，不以全章变化率代替。
- **已发布的项目自定义 Prompt 与新默认文本不一致** → 保留项目覆盖优先级，在设置页可检查/发布新版本；不擅自改用户发布稿。
- **review 调用增加输入长度** → 复用现有预算与失败路径；超限时明确未完成，不伪报通过。

## Migration Plan

无数据迁移。先更新默认模板及回归测试，再升级 review；如质量回归不达标，可回滚该任务默认模板和 review 提示词，已应用章节不自动回退。

## Open Questions

V1 不设置量化“改写幅度”阈值。真实模型对照后再决定是否引入可配置幅度或逐项结构化验收。
