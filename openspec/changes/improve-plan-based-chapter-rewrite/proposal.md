## Why

现有方案提示词已经要求列出可定位的改写拍点、预期效果与三类保留项，但正文提示词仍要求整段重写且禁止大段照抄。这样既可能让模型在指定拍点偷懒，也可能迫使它改坏方案要求保留的有效内容。连续性自检只检查事实衔接，尚不能判断拍点落实与保留项丢失。

## What Changes

- 方案改写正文明确以已确认的方案为执行边界：指定为新增、扩展、调整、压缩、删除的拍点必须有实质变化；未指定改动的有效内容可以保留。
- 正文生成同时保护事实、表达效果、逐字保留三类材料；仅逐字保留项要求字面不变。
- 成稿后对照方案检查拍点落实和保留项回退，报告有证据、可定位的缺口；沿用现有最多一次自动补修与作者确认应用的闭环。
- 自检调用失败时明确呈现“未完成检查”，保留可编辑成稿，不把失败当成无缺口。

## Capabilities

### New Capabilities

- `plan-based-rewrite-adherence`: 方案改写对具体拍点和保留清单的执行与验收。

### Modified Capabilities

- 无。既有入口与合同保持不变，新增能力描述其内部执行与验收行为。

## Non-goals

- 不重做方案结构，不引入严格 JSON 解析、场景切分或逐处接受 UI；不改变按场成稿、直接改写、自动循环。
- 不以整章改动率或段落变化率作为质量门槛；不承诺自动裁决文学优劣。
- 不自动覆盖章节，也不增加无限补修轮次。

## Impact

- API / Prompt：方案改写 draft 的运行时和治理默认提示词、验收提示词与结果解析；保留项目已发布的自定义 Task Prompt 覆盖机制。
- Web：现有自检状态展示与失败分支；可能复用原有 SSE，不新增页面。
- OpenAPI：优先复用 `optimize/continuity-review` 的 SSE 合同；如结果需要明确验收状态，先更新合同再编码。
- 错误码：预计不新增。
