## ADDED Requirements

### Requirement: 方案改写按拍点执行并保护有效原文

系统 MUST 在方案改写正文生成时，将作者确认的改写拍点作为需要落实的改动目标，将保留清单作为保护边界。标记为新增、扩展、调整、压缩或删除的拍点 MUST 在对应内容产生符合方案预期效果的实质变化，不能仅替换近义词。未列为改写目标的有效原文 MUST 允许保留；事实保留允许重写表达，表达效果保留允许改进措辞，仅逐字保留项 MUST 原样保留。单章与分段生成 MUST 遵循同一语义。

#### Scenario: 指定拍点不被原样回抄
- **WHEN** 方案明确要求在可定位的拍点扩展人物反应，而原文只有概括句
- **THEN** 正文生成指令 MUST 要求该处产生具体变化，不能把原概括句或近义改写当作完成

#### Scenario: 非目标段落可以保留
- **WHEN** 方案只要求修改一处对白，并明确保留另一处有效表达
- **THEN** 正文生成指令 MUST 允许另一处沿用原文，不得以整段改动率要求改写它

#### Scenario: 自定义方案兼容
- **WHEN** 作者编辑后的方案没有【2. 改写拍点】或【3. 保留清单】标题
- **THEN** 系统 MUST 继续接受该方案，按用户要求和方案整体意图生成正文

### Requirement: 成稿验收对照拍点与保留清单

系统 MUST 在现有连续性自检中对照原文、已确认方案和成稿，检查有证据的拍点未落实、保留材料丢失以及连续性缺陷。验收 MUST 只报告可定位的实质缺口，MUST NOT 提出方案之外的新润色愿望；仍使用现有 `CLOSED/GAPS` 结果和最多一次自动补修。

#### Scenario: 拍点未落实
- **WHEN** 方案指定的改写拍点在成稿中仍只有原文的概括表达，且预期效果未出现
- **THEN** 验收 MUST 报告 `GAPS`，指出原文位置与未落实的效果，供一次补修使用

#### Scenario: 有效内容被改丢
- **WHEN** 成稿删掉保留清单中的关键人物选择或独特细节
- **THEN** 验收 MUST 报告 `GAPS` 并指出丢失内容与对应方案项

#### Scenario: 合同已落实
- **WHEN** 指定拍点已落实、保留材料与事实连续性没有实质缺口
- **THEN** 验收 MUST 报告 `CLOSED`，不因仍可继续润色而发起新一轮改写

### Requirement: 自检失败状态真实

系统 MUST 将自检调用失败或中断表示为未完成检查，MUST 保留已有可编辑成稿，MUST NOT 将失败解释为 `CLOSED` 或“无缺口”。应用章节仍由作者显式确认。

#### Scenario: 连续性自检请求失败
- **WHEN** 首稿生成成功但自检 SSE 返回错误
- **THEN** 界面 MUST 显示自检未完成及错误，保留首稿供作者审阅，且 MUST NOT 自动补修或显示已收口
