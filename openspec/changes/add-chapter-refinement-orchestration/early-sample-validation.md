# AQ-382 后的前置样章验证

更新：2026-10-07。状态：**验证安排，尚未试跑，尚无质量结论**。

tasks.md 已登记 AQ-380、AQ-381、AQ-382 完成，其证据以确定性测试和 mock 长章为主；本次没有独立复验这些实现。本文件将真实效果反馈提前，不改变已拆分的任务编号、不撤销完成记录，也不替代 AQ-386 的正式发布评测。

## 1. 现在开发者要交付什么

优先提供一份作者能查看的真实候选稿及原文对比，确认当前模型与写作链路值得继续投入。保持新入口受控，不应用到正式章节，不自动发布模板。

开发顺序：完成当前进行中的小步 TDD → 核对试跑所需保护 → 短场试跑 → 一章试跑 → 汇报结果和明确问题 → 针对问题继续对应任务。

如果 AQ-383 已在执行，完成当前测试循环；不要丢弃已有代码或另起实现。如果试跑依赖 AQ-383 的严格完成元数据／预算保护，就先完成对应部分，不把未具备的保护当作已存在。

## 2. 开始前的最小条件

- 选择作者提供或明确授权使用的样章，复制到专用测试章节；冻结原文，并确认候选生成不会保存章节或更新知识库。
- 实际 gateway 调用真实运行模型，检查已发布模板／测试覆盖文本和项目文风确实进入请求。不能把 mock 模型输出当作效果样章。
- 明确使用的运行模型、路由、温度、模板版本、策略、要求与参考快照。开发代理的名称不等于运行模型。
- 能确认输出完整性与范围覆盖；流未成功完成、明显截断、必要事实检查未完成时，样章应判无效，不供作者当成合格成稿。
- 实验前约定最大调用次数和可接受用量，由开发者确认保护确实可执行。缺少自动预算保护时先完成 AQ-383 的相应实现；不能依赖作者一直盯着页面防止无限运行。
- 沿用作者已有的样章及模型调用授权；缺少授权或具体样本时才询问。本次文档修改没有发起模型调用、修改 Settings 或复制业务正文。

## 3. 两步取样，避免首次就跑全部评测

### A. 一个完整短场

优先选 2000～4000 字的完整场景，包含人物互动、情绪变化与明确散场落点。第一轮只验证正文生成质量和目标落实，不把独立片段冒充整章验证。

固定同一原文与要求，生成：原文、现有最佳适用链路候选、新精修候选。两条生成链路使用相同模型设置、文风和等效修改权限；其他注入材料不同处记录清楚，不宣称严格控制了所有变量。

候选名称匿名为 A/B，保留原文作参照。先看结果，再展示各自运行信息。第一轮不根据生成结果反复改评价标准，也不让同一个模型评分代替作者判断。

### B. 一章 10000～20000 字

短场没有明显退化且作者认为值得继续后，再选一个代表性长章，至少含两个执行单位，最好含同一场跨窗及章尾需要修改的目标。继续固定原文、要求与模型设置。

检查全章覆盖、跨范围指代／物件／时序、整场意图、末场落实及必要事件。短场结果好只能支持继续长章试跑，不能据此宣布长章能力过关。

首轮每种样本每条链路各运行一次即可暴露明显问题；有用量授权且值得复核时再重复。这个小样本没有统计胜率含义，正式发布仍执行 evaluation.md 的完整样本集。

## 4. 要求怎么写

使用作者实际编辑目标，不故意选特别容易的要求。第一轮写清三类信息：

1. 必须保留：必要事件、人物关系落点、首尾状态及逐字锁。
2. 需要改善：人物选择／对话、情绪推进、具体细节、准确流畅的文句及节奏，按原文章节选择最重要的两三项。
3. 修改权限与篇幅方向：保留剧情或场内创编，篇幅维持／适当展开／适当压缩。两条比较链路获得相同权限。

写作指导使用项目现有配置，记录完整版本；不为试跑另换一套风格后把结果归因于编排。若调整了模型或指导，另记实验版本并重跑相同样本。

## 5. 作者只需做一次对照判断

开发者提供完整可读文本，以及三处定位对照：本轮主要改动处、一个范围接缝、章尾或散场落点。定位对照帮助阅读，不能替代完整候选稿，也不能只挑最好看的段落。

| 看什么 | 作者回答 |
|---|---|
| 人物是否更鲜明，行为与对话是否贴合 | 改善／持平／退化，并指出一个位置 |
| 情绪与戏剧张力是否由过程产生 | 改善／持平／退化，避免只看强度词 |
| 细节是否准确、有辨识度且不重复 | 改善／持平／退化 |
| 文句与节奏是否自然，是否读着更顺 | 改善／持平／退化 |
| 剧情、信息及首尾衔接是否保住 | 有无实质遗漏或冲突，指出证据 |
| 哪份稿最接近自己的成稿要求 | 原文／A／B，并说明仍需怎样返工 |

作者最终确认偏好；另一个 AI 的评价只能辅助定位问题。此处无需先招募双人评审，正式 AQ-386 仍保留完整盲评门槛。

## 6. 根据结果分流

| 结果 | 下一步 |
|---|---|
| 短场已明显退化或必要事件丢失 | 暂缓外围完善，定位真实请求中的模型、指导、规划和改写问题；修具体原因后重跑同一样本 |
| 短场可用，长章接缝／章尾失败 | 优先修 AQ-382 的范围与状态问题或 AQ-383 的检查／补修；不靠整体加长 Prompt 掩盖定位问题 |
| 文句不错但原文保留过多、目标未落实 | 查决策／锚点／降级和实际改动覆盖，不把“不出错”当成达到修改要求 |
| 输出无完整性证据或频繁截断／暂停 | 样章无效，先补完成判定和预算；不提交精挑的片段让作者验收 |
| 新稿与旧链路相当 | 说明当前主要收益是操作减少；由作者判断是否值得继续，不声称质量显著提升 |
| 作者偏好新稿且长章无明显实质问题 | 继续 AQ-383～AQ-385 的可靠性与整合，再由 AQ-386 正式评测发布；不因两份样章直接公开入口 |

修正问题仍绑定原 tasks.md 和对应票。如果发现新的范围／规格问题，先更新现有 change 再按工作流同步任务，不能悄悄扩大权限或重拆全部任务。

## 7. 每轮交付证据

交付包含：样本编号与源 hash、原文与两份候选的私有查看位置、相同要求／权限、模型及模板版本、实际改动与回退范围、完整性／覆盖检查、用量与耗时、作者反馈、一个主要失败原因及下一步。

实际 usage 缺失时标 estimated 或 unavailable。私有正文不提交 Git，不贴公共 issue；公共记录使用自建 fixture 或授权匿名片段。证据结果不能只写“测试通过”或“模型认为很好”。
