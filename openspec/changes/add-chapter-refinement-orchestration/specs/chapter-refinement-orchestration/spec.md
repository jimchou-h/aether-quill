## ADDED Requirements

### Requirement: R1 创建独立且冻结的章节精修运行

系统 MUST 从已保存章节创建独立 run，冻结原文、版本、要求、策略、已发布模板、模型路由和实际参考材料；不得通过保存中间候选稿触发章节及知识库副作用。创建、查询、订阅与操作 MUST 验证成员权限及 run 所有者。

#### Scenario: 保存正文与候选稿分离
- **WHEN** 作者对已保存的 18000 字章节启动精修，生成了第一个范围的候选稿
- **THEN** 原章节正文、更新时间、摘要、人物状态及索引不改变；候选稿仅属于 run

#### Scenario: 不同作者不能读取候选稿
- **WHEN** 同项目另一作者请求不属于自己的 run
- **THEN** 返回合同约定的不可访问响应，不泄露正文、要求及内部参考材料

#### Scenario: 模板或角色卡在运行中被修改
- **WHEN** Settings 发布新模板，或人物资料在 run 开始后变化
- **THEN** 后续范围仍使用冻结的实际文本与版本；原文事实与参考材料的冲突被记录而非覆盖

### Requirement: R2 单次授权约束自动规划

系统 MUST 默认执行 `preserve-plot`；只有明确选择 `scene-rewrite` 时，才允许场内增删与重排。两者 MUST 保留必要事件、关系落点、伏笔及范围首尾事实。跨场移动、改变范围外正文及后续必要事实 MUST 被判定为边界冲突，不得通过自动循环扩大权限。

#### Scenario: 保留剧情的表达改善
- **WHEN** 作者仅要求提升表达与对话自然度
- **THEN** 可以自动选择 keep、patch 或 rewrite，无需逐场确认，且不删除必要事件

#### Scenario: 场内删除承载必要信息的拍
- **WHEN** 方案拟删除含情绪转折或伏笔的拍
- **THEN** 方案必须指出同场的补偿落点及证据；无法补偿时保留该拍

#### Scenario: 要求超出授权
- **WHEN** 要求把第二场事件搬到下一章，或修改锁定的散场状态
- **THEN** 暂停为 `boundary_conflict`，指出具体冲突；不执行范围外修改

### Requirement: R3 诊断窗口精确覆盖原文

系统 MUST 分开管理诊断窗、场景和写作单位；原文索引 MUST 保留原始换行及 UTF-16 偏移。诊断窗目标 MUST 继承并规范化项目正值至 2000～5000；旧配置为零时，新入口采用自动目标 3000 且解释该行为。只读邻文 MUST 不计入修改目标。

#### Scenario: 含 CRLF 与超长自然段的章节
- **WHEN** 原文含空行、单换行、CRLF、表情字符及超过窗口目标的自然段
- **THEN** 所有诊断目标拼接与原文逐码元相同，无遗漏、重复或代理对断裂；不得以格式归一化改变未修改内容

#### Scenario: 旧入口禁用分段
- **WHEN** 项目旧分段设置为零
- **THEN** 旧入口行为保持，新智能精修明确显示自动分窗并采用自己的范围规划

### Requirement: R4 整章统筹先于成稿

系统 MUST 完成全部诊断窗读取后，生成并冻结一份整章意图与相关场内意图；每个原文场景 MUST 有 keep、patch 或 rewrite 决策。事实 MUST 有可校验的来源，未知状态 MUST 保持 unknown。诊断窗之间的同一场景 MUST 按已验证锚点合并，不得仅凭模型标题合并。

#### Scenario: 问题集中在章节末尾
- **WHEN** 前半章无需修改而最后一场有明确问题
- **THEN** 最后一场进入规划，前半章可 keep；不能在读取前半章后宣布整章处理完成

#### Scenario: 同一场跨越三个诊断窗
- **WHEN** 三个窗口中的场景片段引用连续原文且边界验证通过
- **THEN** 使用同一 sceneId 与场内意图；不得生成三套互相独立的改写目标

#### Scenario: inspect 事实有字段但无原文证据
- **WHEN** inspect 的有值事实引文不能在诊断目标的允许原文范围内确认
- **THEN** 系统 MUST 拒绝该诊断输出并执行既有有界恢复；旧 checkpoint 中同类事实 MUST 重验，不作为已验证事实要求 plan 保留

#### Scenario: inspect 误把只读邻文作为目标事实来源
- **WHEN** 第一版 inspect 因目标范围外证据或其他合同错误被拒绝
- **THEN** 系统 MUST 在既有一次重试中传递具体合同错误并明确邻文只读边界，要求完整 JSON；持续失败时暂停消息 MUST 保留具体原因，不增加调用名额、不放宽证据范围

#### Scenario: 合并场景包含中途状态
- **WHEN** 同场诊断片段依次记录人物在门口、窗边、桌前
- **THEN** 整场入场与散场分别保持门口与桌前，窗边作为有证据的过程事实传递给成稿与检查，不要求其作为整场首尾状态出现

#### Scenario: plan 遗漏可确定继承的边界事实
- **WHEN** 同场原文验证后的边界事实身份明确，plan 未列出该事实且未声明错误值或 unknown
- **THEN** 系统 MUST 从原文索引确定性继承并记录恢复来源，再执行完整合同校验；不能覆盖错误值、借用下一场证据或生成引文

#### Scenario: plan 将已验证过程事实误列为首尾
- **WHEN** plan 首尾事实完整匹配同场已验证过程证据，且该证据不属于相应整场边界
- **THEN** 系统 MUST 按程序角色索引归还过程清单并记录恢复来源，继续严格校验边界事实；不得通过修改事实值或引文完成归位

#### Scenario: 同名事实在一个边界未知而另一边界已确认
- **WHEN** 同一场入场事实为 unknown，而同名散场事实有已验证证据并在 plan 中保留，或反向出现此组合
- **THEN** 必要事实保留校验按 entry / exit 角色进行，不因另一边界的 unknown 报 fact_downgraded；同角色已知事实真正被降级时仍拒绝

### Requirement: R5 写作单位保持场景及预算边界

系统 MUST 优先按场景规划写作单位；默认原文目标约 3500、长度上限 5200，实际执行还 MUST 满足完整输入和预期输出预算。长场只能在可验证的拍边界拆分；低置信度边界 MUST 限制自动创编。预算不能通过删掉必要事实、用户要求或目标原文满足。

#### Scenario: 长场需要拆成两个写作单位
- **WHEN** 同一场原文超过长度或输出预算
- **THEN** 选取安全拍边界，两个单位共享场内意图、进度与状态，并按顺序生成

#### Scenario: 找不到安全写作边界
- **WHEN** 超长单句可分窗读取，但没有可信的动作或对话结束边界
- **THEN** 不将诊断截断点直接用作创编边界；保留相关原文并记录待处理问题，或在必须修改时暂停

### Requirement: R6 顺序替换与有证据的状态传递

系统 MUST 用冻结原文偏移定位初次替换，用候选 revision、hash 与唯一锚点定位补修；所有范围 MUST 无交叠且完整覆盖。后续单位 MUST 接收真实已接受前文及只读未来原文，不得用模型摘要替代真实邻接正文。状态提取 MUST 引用可验证的来源片段。

#### Scenario: 第一单位扩写导致候选稿变长
- **WHEN** 第一单位候选稿比原文增加 600 字
- **THEN** 第二单位仍由原文偏移准确定位；其前文上下文采用扩写后的已接受内容

#### Scenario: 补修使用过期定位
- **WHEN** 补修请求中的候选 revision、hash 或引文与当前候选不匹配
- **THEN** 拒绝替换，不把旧补丁应用到新文本

#### Scenario: 原文未交代的物件
- **WHEN** 状态模型声称人物手中有钥匙，但无法提供原文或候选稿证据
- **THEN** 不接受该状态事实，下一范围不能据此新增动作

#### Scenario: 成稿与程序门禁使用同一组逐字锁
- **WHEN** plan 为当前写作单位明确标注不可改措辞的原文块
- **THEN** 成稿输入包含该单位的具体逐字锁、冻结用户要求和章级语义事实；范围外锁不传入，事实证据引文不被当成字面锁；真正丢失逐字锁的候选仍拒绝

### Requirement: R7 有限补修与可解释的候选接受

系统 MUST 先执行程序门禁，再检查本轮目标和必要事实。每单位最多初次改写一次和有证据的局部补修一次；暂时性失败最多重试一次且计入调用预算。最终接缝最多一轮定位修复并重检。主观评分或新提出的风格愿望 MUST NOT 单独触发无限循环、整章重写或回滚。

#### Scenario: 成功 end 之前连接断开
- **WHEN** 已收到非空正文但流提前结束，或 finishReason 为 length、content_filter、unknown
- **THEN** 不接受半成品；按规定缩小范围或重试，仍失败则暂停并保留上一 checkpoint

#### Scenario: 检查只提出更丰富的风格建议
- **WHEN** 候选满足目标与必要事实，检查只说可以更丰富而无具体退化证据
- **THEN** 保留候选并记录建议，不启动下一轮自动重写

#### Scenario: 补修仍丢失必要事件
- **WHEN** 唯一补修后仍存在可定位的必要事件遗漏
- **THEN** 恢复该单位原文并重检接缝；若原文回退也不能接上已接受前文，暂停，不能把冲突稿标为 ready

### Requirement: R8 运行预算与恢复不重置补修次数

系统 MUST 为每次执行尝试设置默认 80 次模型调用及 30 分钟活动时间预算，包含重试并预留最终验证。估算与供应商实际用量 MUST 区分。预算耗尽或 context 无法容纳时 MUST 暂停，显示已处理范围及原文保留尾部。继续 MUST 使用 checkpoint，累计历史用量并保留单位补修计数。

本 requirement 的预算亦适用于 plan 合同恢复。系统 MUST 先校验 plan；仅在与已验证事实索引唯一精确匹配时确定性回填缺失证据字段，并再次全量校验。仍违规时最多一次额外 plan 调用，网络／解析／合同重试共用名额且计数持久化。系统 MUST NOT 删除有值 Fact 或将其改为 unknown 以放行；仍无法验证的全章必要事实 MUST 暂停。局部编辑指令无法验证但其范围和全部必要事实独立有效时，可整场 keep 并显式警告。

#### Scenario: plan 单个有值 Fact 偶发缺字段
- **WHEN** 首次 plan 无法从已有证据安全回填字段，唯一一次额外 plan 调用返回合法合同
- **THEN** 复用已完成诊断，仅在全量事实与范围校验通过后继续；额外调用计入预算且不产生新的自动重试循环

#### Scenario: plan 连续违约影响必要事实
- **WHEN** 额外调用后必要 Fact 仍不能验证
- **THEN** 暂停为 invalid_model_output，保留诊断与恢复计数，不启动正文生成，不删除事实让校验通过

#### Scenario: 中途预算耗尽
- **WHEN** 仍有未处理范围且达到预算
- **THEN** 状态为 paused/budget_exhausted，不可应用；继续可获得新的执行尝试预算，但不能重做已接受单位或重置其补修次数

#### Scenario: 缺少 tokenizer 或供应商 usage
- **WHEN** 只有保守字数换算可以用于预算
- **THEN** 用量标记 estimated 或 unavailable，不展示为实际 token 消耗或精确费用

### Requirement: R9 订阅断开与运行取消分离

创建 run MUST 与 SSE 观察解耦；订阅断开 MUST NOT 取消后台执行。明确 cancel MUST 中止当前调用并保存 checkpoint；取消后的迟到回调 MUST 被 attemptId 和 revision 拒绝。同一作者同一章节 MUST 至多有一个 queued/running run。

#### Scenario: 关闭弹窗再打开
- **WHEN** 作者关闭精修弹窗，随后重新打开或刷新页面
- **THEN** run 继续执行，前端通过快照恢复状态；未接受的临时流内容不冒充已接受候选

#### Scenario: 取消与模型结束竞态
- **WHEN** cancel 已被接受而旧模型调用随后返回正文
- **THEN** 旧回调不能覆盖取消后的 checkpoint 或修改 run 状态

#### Scenario: 重复点击开始
- **WHEN** 同一个 clientRequestId 重发相同创建参数
- **THEN** 返回同一个 run；相同 key 携带不同参数或已有其他活动 run 时按合同返回冲突

### Requirement: R10 明确持久化与服务重启边界

配置 PG 时，系统 MUST 使用独立 run 存储并在阶段、单位接受和暂停处写 checkpoint；未配置 PG 时 MUST 明示进程重启不能恢复。P0 MUST 仅声明单 API 实例支持。服务重启后原 queued/running run MUST 变为 paused/process_restart，不能自动再次调用模型。终态记录 MUST 有七天保留及清理策略。

#### Scenario: PG 下 API 重启
- **WHEN** run 在第三单位调用中发生服务重启
- **THEN** 可以恢复前两个已接受单位与冻结材料，第三单位临时流内容被舍弃，等待作者继续

#### Scenario: 无 PG 的 API 重启
- **WHEN** 内存模式服务重新启动
- **THEN** 不宣称可恢复旧 run；前端展示既有运行记录不可用的明确说明

### Requirement: R11 完整验证与一次最终确认应用

系统 MUST 对整章覆盖及每个相关场景、接缝完成最终检查后，才标记 ready 或 ready_with_issues。无法完成检查时 MUST 暂停。候选对比 MUST 显示原文保留范围及未解决问题；确认应用 MUST 复用现有 optimize/apply、冻结的版本锁和摘要保留策略，且使用返回的真实正文刷新 UI。

#### Scenario: 原文在运行中被作者修改
- **WHEN** 作者修改并保存章节后尝试继续或应用旧 run
- **THEN** 按既有 1307 版本冲突语义阻止，不自动把旧范围补丁迁移到新正文

#### Scenario: 含保留原文警告的完整候选
- **WHEN** 部分低置信度范围保留原文，完整覆盖和最终检查已完成且无未解决的阻断冲突
- **THEN** 状态为 ready_with_issues，需作者明确查看警告后确认应用

#### Scenario: 未完成验证的部分成果
- **WHEN** run 因预算或上游故障暂停
- **THEN** 可以查看部分候选与未处理尾部，不能调用精修 UI 的应用动作

### Requirement: R12 新入口与模板必须经过发布验收

系统 MUST 将新增 Prompt 按 utility/writing 分阶段管理，使用现有草稿、发布、回滚和版本追踪能力；MUST 覆盖模型档位、检索、叙事注入和文风样本分类。新模板或入口 MUST 在确定性测试、旧链路回归和真实模型长章评测完成后开放；不得将离线检索评测或 mock 测试宣称为文学质量证明。

#### Scenario: 新 rewrite 模板调用
- **WHEN** run 为当前范围生成正文
- **THEN** 使用冻结的写作指导及适用样本，排除当前章节自身样本；不把整章正文作为 embedding query

#### Scenario: 只有离线测试通过
- **WHEN** 测试通过但真实模型长章质量与稳定性尚未评测
- **THEN** 任务仍保留发布门禁未完成状态，新模板不自动发布、入口不作为默认可用功能
