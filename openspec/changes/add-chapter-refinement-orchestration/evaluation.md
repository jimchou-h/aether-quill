# 验证、评测与发布门禁

状态：2026-10-06 **评测设计，尚未执行**。本文件不报告任何 PASS、模型胜率或生成质量结果。真实运行模型由项目配置决定，DeepSeek-v4-flash 作为开发执行者不构成模型能力证据。

## 0. 开发中前置样章验证

2026-10-07 补充：在 AQ-382 后安排 [early-sample-validation.md](early-sample-validation.md) 的真实短场与长章对照，先取得作者反馈，再继续外围完善。必要保护不足时先完成 AQ-383 对应部分；不重新拆票，也不降低以下正式发布门槛。前置试跑结果尚未产生，不能声称质量已经验证。

## 1. 三类证据

| 证据 | 能回答什么 | 不能证明什么 |
|---|---|---|
| 纯函数／API／UI 确定性测试 | 范围、完整性、预算、授权、恢复和应用行为是否正确 | 成稿有无文学感染力 |
| 真实模型长章运行 | 当前模型／模板／策略组合是否稳定，有无真实截断及目标遗漏 | 所有题材和未来版本质量必然相同 |
| 双人盲评及原文对照 | 人物、节奏、表达、感官细节是否改善，有无隐性剧情退化 | 程序能够自动识别全部文学缺陷 |

新链路发布需要三类证据。`pnpm eval:rag` 当前侧重离线 GS-R 与已有测试，不能替代长章成稿评测；现有 GS-R/GS-G/GS-C 的门槛继续适用。

## 2. 确定性用例矩阵

测试采用自建非敏感小说 fixture 与脚本模型。断流、错误 JSON、造假引文等通过注入 gateway 模拟，不依赖真实模型偶然犯错。每项断言观察结果与边界，不只断言实现调用次数。

| ID | 输入／故障 | 必须观察的结果 |
|---|---|---|
| E01 | CRLF、空行、单换行、表情与超长段 | 窗覆盖原文；代理对完整；keep 拼回逐码元相同 |
| E02 | 自然段长度极不均匀 | 按累计长度规划诊断；不出现仅按段落数量平均导致的巨窗；独立验证写作预算 |
| E03 | 项目旧设置 0、500、3000、20000 | 新入口分别自动／规范化，返回原因；旧入口行为不改变 |
| E04 | 同一场跨三窗，另一场标题相同 | 连续场景合并；独立场不因同名合并；仅使用可验证锚点 |
| E05 | 超过 5200 的单场及计划扩写 | 安全拍拆分、共享 brief、输出预算生效，最终不丢场内落点 |
| E06 | 超长单句且无安全边界 | 仅诊断可分割；不擅自创编；原文保留并警告或暂停 |
| E07 | 非空流缺 end、length、unknown、过滤 | 不接受临时稿；有限重试／缩范围；随后暂停且旧稿仍在 |
| E08 | 原文未知属性、模型假引文、知识卡冲突 | 状态不补造；参考不能覆盖原文；未定位问题不自动替换 |
| E09 | 候选长度变化、重复引文、过期 revision | 后续 source 偏移不漂移；错误补丁拒绝；未命中内容完整保留 |
| E10 | 前半章 keep、章尾必要事件遗漏 | 诊断与最终验证覆盖章尾；未检查完整章不得 ready |
| E11 | review 无限提出风格愿望；一次补修仍失败 | 不追评分循环；补修计数有界；回退原文后重检接缝 |
| E12 | 调用、活动时间或完整上下文预算耗尽 | 包括重试计费；预留检查；paused，不开放应用；估算标识正确 |
| E13 | 合并稿接缝出现称谓／物件冲突 | 定位修复一轮并重检；硬冲突未消除时暂停；不整章重写 |
| E14 | cancel 与 completion、resume、discard 竞态 | attemptId/CAS 防止迟到覆写；未接受临时稿舍弃 |
| E15 | SSE 断开、多观察者、重连缺事件 | 后台继续；snapshot 权威恢复；旧 provisional 内容清空 |
| E16 | PG checkpoint 后重启、无 PG 重启 | PG 恢复为 paused 等待继续；内存模式不虚报重启恢复 |
| E17 | 同项目其他作者读取；权限中途撤销 | 正文与 Prompt 不泄露；新调用停止；查询遵循鉴权合同 |
| E18 | 原章节变化后 resume／apply；重复创建 | 1307 阻止；不自动重定位；幂等不重复启动模型 |
| E19 | paused／终态到期、活动任务、discard | 到期／丢弃正文按合同清理；活动任务不误删；旧 run 无法应用 |
| E20 | plan 有值 Fact 缺字段、二次违约及证据歧义 | 仅确定性证据回填或一次额外 plan 调用；不重跑诊断、不丢必要 Fact；不安全时暂停，合法局部降级显式警告 |

额外矩阵：五个新模板的档位、文风样本、摘要／记忆注入及冻结 override；provider completion 字段的旧调用兼容；旧 apply 安全处理、摘要及索引副作用；旧所有写作入口回归。

## 3. 长章真实模型固定集

初期固定 **6 个完整章节，每个运行两次**，至少覆盖以下组合；同一份原文、要求、模型与模板版本使用明确编号冻结。新链路与现有最佳适用链路分别两次，共 24 次完整运行；先做小样本 smoke 可节约试错，但不能拿 smoke 代替发布评测。

| 类型 | 长度 | 重点 |
|---|---|---|
| 双场，人物互动为主 | 约 10000 | 对话声音、前后场目标衔接 |
| 单一长场 | 约 10000 | 场内意图与多个写作单位一致 |
| 多场，环境／行动穿插 | 约 15000 | 节奏疏密、换时换地、避免状态漂移 |
| 长场含局部扩写要求 | 约 15000 | 输出预算、原文必要信息、篇幅方向 |
| 双场，末场问题集中 | 约 20000 | 完整读取、章尾覆盖、有限调用 |
| 长章含参考材料冲突 | 约 20000 | 以原文事实为准、系统规则逐字锁 |

另做 30000 上限的结构 smoke，不作为文学盲评主样本；超限请求必须拒绝。fixture 选择不包含真人私密资料；日志和分享结果不附作者私有全文。

比较链路按任务适用性在运行前固定：局部表达目标可用直接改写；需要场内增删则用已有方案改写／按场成稿。不能故意选不适用入口制造胜率。两边使用相同原文、要求与等效权限、模型设置；记录旧链路人工操作和调用次数，不假定预算完全相同。

## 4. 初期发布标准

以下是本提案的初期工程门槛，需在正式实验前确认；不在看见结果后调低门槛。不是已验证的文学定律。

### 4.1 确定性与稳定性

- E01～E20 及旧功能回归全部通过，未执行项不得记为 PASS。
- 冻结原文覆盖、逐字锁、越界替换及不完整流接受等程序硬错误为零。
- 12 次新链路正常运行至少 11 次在默认一次尝试预算内形成可最终审核的完整稿；任何一次未完成必须正确暂停，不能假成功。人为故障注入单列，不混入此分母。
- 正常运行除一次启动、一次最终审核外，额外需要作者操作的运行不超过 1/12；用户主动取消不算失败。
- 抽查全部成稿的必要事件和首尾事实，无法解释的实质遗漏或改变为零；模型「说检查通过」不是证据。
- 用实际供应商 usage 统计调用与 token；缺 usage 的运行明确 estimated，不把估算当节省成本实绩。耗时记录 P50、P95 与最大值，不预先承诺模型速度。

### 4.2 双人盲评

隐藏链路名称，提供原文、同一编辑要求和匿名候选稿。两名熟悉中文小说的评审独立给 1～5 分，分歧超过 1 分或涉及必要事实时复核，不以分数均值掩盖剧情错误。

| 维度 | 观察方式 | 初期要求 |
|---|---|---|
| 本轮要求落实 | 逐个检查明确改动目标及章尾 | 遵循既有约束评测要求，且无必要目标被漏掉 |
| 人物与关系推进 | 行为动机、声音、关系落点 | 不低于原文；不能只增加强度形容词 |
| 情绪与戏剧张力 | 目标／阻力／选择／变化是否可见 | 平均 ≥4.0，不靠每段同一模板制造起伏 |
| 感官与表达 | 细节准确、有辨识度、与当下事件相关 | 平均 ≥4.0，感官数量配额不作为加分依据 |
| 文句与节奏 | 准确、自然、疏密、重复与摘要化 | 平均 ≥4.0；反复套话或大段漏写须扣分 |
| 章节连续性 | 接缝、物件、指代、时序、首尾衔接 | 同时满足既有连续性基线，并无实质状态冲突 |

12 组匿名对比中，新链路至少 8 组被多数／复核判定更好，明显退化不超过 1 组，其余可以持平。重复运行按配对记录，报告样本量和分歧，不能泛化为「所有小说质量提高」。

既有 RAG 基线要求的相关性均分 4.2 等门槛仍按原维度执行；这里的 4.0 文笔子项不取代或调低它们。约束遵循、连续性与引用有效性对应 GS-G/GS-C 的数值以 `.docs/RAG评测与验收基线-v1.md` 为准。

## 5. 记录与发布

每次至少记录：fixtureId、源 hash、策略、要求版本、模型路由及实际模型、温度、五个模板版本、resolvedPolicy、attempt 次数、调用／usage、运行／暂停结果、所有回退范围、最终检查覆盖、人工操作、盲评和错误 trace。

证据保存到本 change 下 `evidence/`，该目录实施评测时再建立。不得提交密钥、真实用户正文或含敏感内容的完整 Prompt；保留可重放的自建 fixture 与必要 hash／匿名片段。

开发自检使用仓库实际脚本：

```text
pnpm --filter @aether-quill/api lint typecheck test build
pnpm --filter @aether-quill/rag-orchestrator lint typecheck test build
pnpm --filter @aether-quill/web lint typecheck test build
pnpm -r lint
pnpm -r typecheck
pnpm -r test
pnpm -r build
pnpm eval:rag
```

共享包变化要覆盖其依赖包；没有 test script 的包不能伪造单包测试通过。新增评测脚本的命令由实施时写入 package.json 和本文件，本文不假装它已经存在。

全部门禁完成才发布模板并开放入口；不足时保持草稿和受控入口，记录未满足项。回滚按 design.md 停止新 run 创建，保留章节与已接受候选，不通过删除章节或 run 表「修复」结果。
