# B2 收口：散场状态证据的可信边界（W6 关闭）

日期：2026-10-07。承接 `acceptance-closure-plan-2026-10-07.md` §4，前置批次 B1 已完成。

## 结论

**W6 已关闭**：把入场片段改名为 `exitAnchorQuote` 的反例，现在由程序按「锚点之后仍有同一状态的后续变化」判为 `superseded`，不再进入确定状态集合，也不向下游传播。

同时按计划先同步了内部输出合同（`prompt-design.md` §6.1 + 三处 review 提示镜像 + 类型），把「引文命中」与「末态成立」分成两层：命中只证明片段存在，末态成立还要程序确认位置与顺序。

**未解决（不属于 B2）**：人物行为是否真的改变状态，仍依赖 review 与 AQ-386 的模型评测。程序判定中的「相关性」是共享内容词的近似，不是语义判断。

## 改了什么

### 1. 内部输出合同（`prompt-design.md` §6.1、`chapter-refinement.util.ts`）

新增散场状态的**末态证据记录**：

```ts
interface RefinementStateEvidence {
  exitAnchorQuote: string;                      // 证明末态成立的候选片段
  basis: 'exit_confirmation' | 'last_change';   // 末尾确认 还是 最后一次相关变化
  supersededBy?: string;                        // 之后仍有的后续相关变化
  uncertain?: boolean;                          // 重复引文 / 末尾对白 / 跨段持续
}
```

- 偏移**一律由程序定位**，不采信模型给出的任何数字；锚点出现多次即位置不唯一。
- 扁平 `exitAnchorQuote` 保留为兼容形式（语义相同，但无法表达依据与不确定性）。
- 三处 review 提示镜像同步：`services/api/.../chapter-refinement.util.ts`（模板常量 + 整章接缝检查段）、`packages/prompt-templates/src/templates.ts`、`services/rag-orchestrator/src/generation/task-prompt-defaults.ts`。

### 2. 程序判定（`chapter-refinement.util.ts`）

`verifyRefinementStateFact` 由 4 类结果扩为 6 类：

| 结果 | 含义 | 是否传播 |
|---|---|---|
| `evidence` | 锚点唯一命中、可定位、非对白、之后无后续相关变化 | 是（附 `start/end/basis`） |
| `superseded` | 锚点命中但之后仍有同一状态后续变化（入场拿着、后面放下） | 否 |
| `ambiguous` | 重复引文 / 落在对白内 / 位置不可唯一定位 / 自标不确定 | 否 |
| `historical` | 只有改写前原文能命中 | 否 |
| `unknown` | value=null | 否 |
| `conflict` | 凭空状态 | 否 |

新增的纯函数：`splitRefinementEvidenceSegments`（句段切分，切点含句末标点与逗号/分号/换行）、`locateAllQuoteOccurrences`（引号字形无关的全文定位，返回偏移）、`isInsideDialogue`（引号配对深度）、`sharesContentToken`（CJK 二字组 / 长度≥3 拉丁词交集）、`resolveStateEvidence`。

### 3. 证据绑定候选版本与失效（`chapter-refinement.engine.ts` / `chapter-refinement.types.ts`）

- `RefinementStateFact` 增 `candidateRevision` / `candidateHash` / `anchorStart` / `anchorEnd` / `basis` / `sceneId`。
- 新增 `invalidateStateFactsForUnit(unitId)`：补修稿取代候选、单位回退原文、整章接缝回退三个时点让该单位旧候选上的证据失效，须等复检产生新证据才重新传播。
- 传播过滤：只有「证据登记的候选版本 == 该单位当前候选版本」才进入下游提示；**缺版本信息（旧 checkpoint）按不确定处理、不传播**。
- 续跑反推版本时，状态证据与问题账本**共同参与**（只从问题账本反推会让「没有问题的单位」版本缺失，其已确认证据被误判为版本不匹配）。
- 必要事实与逐字锁不受影响：`protectedSpanIds` 逐字锁仍由原门禁强制，value=null 的事实仍不是锁（不凭空造锁，也不把有值锁降 null 放行）。

## 红灯与绿灯

原则：先用原合同写出失败测试，再改实现；改完把判定临时退回旧口径复跑一次，确认新用例真的会失败。

**红灯（把 B2 新增判定屏蔽后复跑 `util.test.ts` + `engine.test.ts`）：7 fail / 111 pass**，失败项全部是 B2 新例：

- `B2/W6 入场片段冒充末态锚点：之后有同一状态后续变化时不得判为确定末态`
- `B2/W6 入场引文冒充末态锚点：真实运行中不进入确定状态，也不传给后续单位`
- `B2 重复引文无法确定末态位置`
- `B2 同物件多次转移`
- `B2 末尾对白中的状态陈述不等于叙述末态`
- `B2 事实自标不确定 / 自报后续变化`
- `B2 末态锚点重复/唯一由程序定位，不采信模型标注`

**红灯（屏蔽引擎侧失效/过滤后复跑 `engine.test.ts`）：2 fail / 62 pass** — 接缝回退失效、旧 checkpoint 缺版本不传播。

**绿灯（恢复实现后）**：api 全量 611 tests / 610 pass / 1 skip（PG 未配置）；全仓 lint、typecheck 全绿。

新增用例分布：`chapter-refinement.util.test.ts` 7 例（判定层），`chapter-refinement.engine.test.ts` 6 例（真实引擎流程：W6 不传播 / 补修改变候选 / 接缝回退失效 / 续跑保存同版本 / 旧记录缺版本不传播 / 逐字锁与 null 锁）。

判定真实引擎流程时按「前文已确认状态」小节断言，而不是整段 prompt——已接受前缀本就包含上一段正文，按整段断言会给出假阳性。

## 已关闭 / 仍未覆盖

- **已关闭**：W6 原反例；入场片段冒充末态锚点；重复引文；同物件多次转移；末尾对白；候选变更后的旧证据污染。
- **仍未覆盖**：人物行为的语义判断（同一个物件「拿着」与「放下」在纯语义层面的普适识别）留给 AQ-386；程序的「后续相关变化」按共享内容词近似，极端长句跨段持续状态仍可能判为可确认。
- **未做**：没有为末态证据新增每单位一次模型调用（按计划复用既有 review）。
