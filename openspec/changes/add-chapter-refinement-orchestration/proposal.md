## Why

已有章节的方案改写、自动循环和按场成稿分别承担整章规划、局部补修和范围改写。作者需要手动判断路径、应用中间稿，再切换工具；10000～20000 字长章还存在字数分段切开完整场景、跨窗信息不足和循环成本放大的问题。

增加章节精修编排，让作者设置一次目标，系统整章统筹并执行有限修订，最终只审核一份完整候选稿。

## What Changes

- 增加文笔优化中的「智能精修」入口，默认保留剧情，可选场内创编。
- 新建 API 运行与观察接口：分窗阅读 → 整章改写意图 → 顺序范围改写 → 有限缺口补修 → 整章检查。
- 将诊断窗与执行范围分开；识别场景边界，过长场景以情节拍／句段边界续接，携带真实成稿状态和只读邻接内容。
- 冻结原文、要求、模板及参考上下文；程序管理范围偏移、逐字锁、输出完整性、版本与预算。
- 增加独立 run/checkpoint 存储：配置 PostgreSQL 时持久化，未配置时使用有明确重启限制的内存实现；不新增业务 JSON 文件。
- 写作指导只用于正文阶段；诊断与检查只给有原文证据的具体问题，避免固定感官配额和无限润色。
- 复用现有模型适配、任务 Prompt 设置、引用定位、SSE 展示及最终章节 apply；旧入口保持兼容。

## Non-goals

- 自动覆盖已保存章节；无条件承诺文学质量或每次改写都更好。
- 跨场重排整章剧情、改变后文落点、自动完成多个章节。
- 改写旧模式语义、旧分段配置的 `0` 含义或自动循环的每窗轮数语义。
- 新模型供应商、模型能力假设、独立队列平台或多副本后台执行。
- 本轮开发、模板发布、运行真实模型评测或创建 tracker issues。

## Capabilities

### New Capabilities

- `chapter-refinement-orchestration`：长章分窗阅读、整章意图、范围执行、有限修订、完整候选稿与可恢复运行。

### Modified Capabilities

无旧产品能力的语义修改。公共生成 SSE 可添加可选完成元数据；共享工具抽取必须保持旧调用结果。

## Impact

- `services/api`：独立 refinement service/engine/store/controller、Prisma run 表与迁移、章节应用和模型调用的窄适配。
- `apps/web`：独立精修面板／composable，现有章节菜单与对比、进度组件复用。
- `services/rag-orchestrator`、`packages/config`、`packages/prompt-templates`：新任务分类、冻结上下文与完成元数据；不替换旧模板。
- `openapi/`、`packages/shared-types`：新增合同与生成类型，先于实现。
- 新生成链路须完成既有 RAG 回归及本 change 的长章质量评测后再发布。
