# AQ-383：plan 合同违规的有界恢复

日期：2026-10-07。状态：设计补充，待 AQ-383 实施与测试；本轮不改代码。任务编号及原完成记录保持不变。

## 1. 问题与方向

2026-10-08 修正规则：事实进入索引前须核验实际原文与允许范围；合并片段的中途事实保留为过程事实，不当整场首尾。验证身份明确的边界事实可由程序恢复整项遗漏，已有错误字段或 unknown 不覆盖。实现与验收见 [事实合同修复](fact-contract-fix-2026-10-08.md)，本补充优先于下面旧版“只补来源字段”的限制。

作者反馈：plan 中一个有值 Fact 缺少合同字段会使整章直接 paused；重新运行可以通过。复跑成功支持偶发输出违约的判断，但不能据此放宽校验。

保留现有安全行为：无效 plan 不能进入写作。增加一个有界恢复流程，避免通过重跑全部诊断才能恢复；不得靠默认字段、删除事实或降成 unknown 让校验通过。

## 2. 执行顺序

1. 初次 plan 完整输出后，运行 schema、ID、引文与覆盖检查，记录精确错误路径和类型。截断或缺成功 end 先按流完整性规则处理，不当作完整 JSON 字段问题。
2. 若输出可解析，仅字段缺失，尝试一次确定性的证据回填并重新全量校验。无需调用模型；只有满足第 3 节的条件才允许回填。
3. 仍不合法且预算允许时，重新调用 plan **一次**。提供冻结的原始规划输入、已验证事实索引、必要错误路径及允许的合同；要求重新输出完整 JSON，不输出补丁或正文。不得重复 inspect 全章、改变要求、引用无效 plan 作为事实来源。
4. 对第二次完整输出最多进行一次同样的确定性回填，然后重新全量校验。
5. 仍不合法时，仅按第 4 节允许的条件降级；其余 paused/invalid_model_output。拒绝候选，保存已验证诊断成果、错误位置及恢复次数。

当前 plan 节点最多初次调用 + 一次额外调用。网络、解析、schema 和流截断重试共用这一个额外调用名额，不叠加多层 retry。调用均计入 AQ-383 的预算，预留最终检查预算；预算不足直接 paused/budget_exhausted。

恢复次数写 checkpoint，自动恢复或 resume 不重置已消耗名额。名额耗尽后 resumable=false，成果可查看；需要再试时明确新建 run。不得用自动 resume 或新的内部 attempt 重置计数。

## 3. 字段回填允许与禁止

允许：从当前 run 已验证的 inspect 事实索引恢复遗漏的来源字段，候选已提供的 key、value 和已验证作用范围必须与 **唯一一条**索引事实精确匹配。复制其 sourceBlockId、anchorQuote 等合同字段后，再验证真实原文命中和允许读取范围。没有作用范围或同值有多个来源时不可猜测。

**引文唯一重锚（2026-10-07 补充，真实样章验证新增）**：当候选声明的 block 内找不到 anchorQuote，但该引文在全文（场景内事实限定在该场 sourceBlockIds 内，全章 protectedFacts 不限）中**唯一一个** block 内逐字出现时，把 sourceBlockId 重锚到该 block，并记录恢复来源（`method: 'quote_unique_block'`）。依据是引文自身的唯一证据位置，不是距离或语义相似度；命中 0 个或多个候选一律不重锚，保留违规。动机：上游 inspect 与 plan 都把「信件正文」归到相邻的「昭儿：」行（b68）而正文在 b69，逐字引文正确但归属错位，导致整章暂停。

回填只补缺失字段，不覆盖已有字段；缺字段与字段值错误分别记录。没有事实 key/value 或无法唯一匹配时留给唯一一次模型重试。所有恢复字段均记录来源索引 ID 和恢复方式。

禁止：
- 自行生成引文、按距离选最近段、用语义相似度替代唯一证据匹配。
- 把有值 Fact 改成 value=null，删除不合法 Fact，或过滤整个 protectedFacts 列表。
- 对无效 sourceBlockId、错误引文、冲突 value 进行**静默**覆盖（引文唯一重锚必须记录来源与恢复方式，且只认逐字唯一命中）。
- 通过宽松 schema、as 断言或补空字符串绕过验证。
- 让重试引入新事实、改变策略锁或把只读邻文变成修改范围。

## 4. 降级的允许范围

仅局部场景的编辑决策无法验证，但该场原文范围、全部必要事实、入场／散场及全章保护事实已独立验证时，可将 **整场**改为 keep，记录 retained_original 和具体未完成目标。保留该场原文，不接受无效 plan 的局部指令。完整检查后最多 ready_with_issues，最终由作者确认。

以下情况不能降级为可写 plan，必须暂停：全章 protectedFacts 无效、已知 Fact 缺少可恢复证据、场景归属不明、覆盖交叠或遗漏无法恢复、必要首尾状态不确定、降级会破坏相邻场依赖，或该修改是不可省略的必要目标。

因此，单个有值 Fact 缺字段的实际问题优先走证据回填或一次 plan 重试；两者都失败时仍安全暂停。不能为降低暂停率丢弃事实。

## 5. 最少测试矩阵

| 用例 | 预期 |
|---|---|
| 单个有值 Fact 缺来源字段，与已验证索引唯一匹配 | 确定性回填后全量通过，无额外模型调用，有恢复记录 |
| 缺字段无法回填，第二次 plan 合法 | 仅一次额外 plan 调用，不重跑 inspect，全部事实及覆盖验证后继续 |
| 两次 plan 都不合法 | 不再自动调用，不启动 rewrite；暂停并保留诊断 checkpoint |
| 相同 key/value 有多个来源、缺 key、已有错误引文 | 不猜测、不覆盖；进入一次重试或暂停 |
| 全章必要 Fact 仍无证据 | 不删 Fact、不改 null、不全章 keep 冒充完成；暂停 |
| 仅一场编辑指令不合法，独立事实和范围均有效 | 整场 keep，其余合法场可继续；最终显示警告与未完成目标 |
| 预算不足、取消、节点恢复、迟到回调 | 不产生越预算或取消后的调用；恢复次数不清零，旧回调无效 |
| 流截断后 schema 也失败 | 共用一次额外调用名额；不能连续触发网络、解析、schema 各一次 retry |

自动化测试用可控 gateway 模拟违约，断言正文是否接受、事实是否完整、诊断是否复用和调用边界。真实模型样章另记录合同首次违规率、自动恢复率及最终暂停率；不能只报告复跑成功。
