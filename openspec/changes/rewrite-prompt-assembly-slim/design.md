## Context

改写正文走 system（全局+项目+任务）+ user（叙事/证据/文风/业务 prompt）。任务层与 user 尾部重复「只出正文/别照抄」；业务块包在【用户需求】内且原文偏中。

## Decisions

1. **标签重命名**：【叙事上下文】→【参考上下文】；【用户需求】→【任务输入】。全局统一，避免「需求」误解。
2. **约束单层**：task system 只保留角色、冲突优先级、硬约束；「怎么改」只在 user【输出要求】。
3. **顺序**：参考 → 证据 → 文风 → 任务载荷（目标/要求/可选角色关系 → plan → original → 输出要求）。
4. **出场角色/关系**：本轮仍保留注入（与叙事去重留后续），避免行为回归范围过大。

## Risks

- 已发布到 DB 的旧 task prompt 仍含「叙事上下文」字样；运行时若用存库文本，标签与 assembler 新块名可能短暂不一致。可接受：用户可在设置重发默认，或下次 sync 覆盖。

## Migration

无数据迁移。部署后新请求即用新拼装；建议在 Prompt 设置对 draft/direct-draft 重置为仓库默认。
