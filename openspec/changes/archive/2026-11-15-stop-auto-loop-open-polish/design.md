## Context

历史两类白名单同时写在 system 默认与 user 追加指令中；当前项目还发布了“只查清单”的自定义稿。仅修改其中一层不能可靠恢复主动纠错。Git 历史显示 2026-09-27 收窄的是诊断范围，提交前后实际续跑条件均为 high 或诊断不完整；本次不修改此判断。

## Goals / Non-Goals

**Goals:** 主动基础纠错、用户额外重点及上轮改坏；没有 high 且诊断完整就停。

**Non-Goals:** 不扩大为无终点润色，不改定位、删除、模型及切窗机制。

## Decisions

1. **主动基础检查与用户重点并行。** 基础检查包括错字/病句/搭配、同义重复/重复解释、指代和动作主体、动作及状态矛盾、明确设定冲突与视角越界。用户未点名仍须检查；不要求错误严重到影响理解才报告。
2. **证据与修正边界。** 条目须引用当前正文、说明具体问题并给出局部修法。纯主观“还能更好”不报；不靠扩写或新增事实填补无法确认的条件。JSON、编号和锚点协议保持兼容。
3. **统一有效范围。** user 末尾明确基础检查不因用户清单而省略，移除仅两类旧白名单；目标项目自定义稿同步更新。保留诊断 omitProjectSystemPrompt，避免项目文风自动变成修改待办。
4. **控制循环。** 可确认且需要修正的条目标 high；已解决的不重复报。无明确问题返回空 items，保留 medium/low 不续跑、诊断丢弃不误报收敛及硬轮数上限。
5. **最小发布。** 模板包此前没有此任务，新增 v1.0.0 治理副本；API 与编排默认同步。当前项目通过已登录设置页保存回滚点、替换并发布，不直接改运行中 JSON、不读取登录凭证、不覆盖其他项目。

## Risks / Trade-offs

- 中性组装、定位和收敛回归只能验证指令及执行合同，不能证明真实模型实际纠错召回提升；作者另行试用。
- 只更新仓库种子不会覆盖自定义发布稿，必须核对当前项目的发布版本与文本指纹。
