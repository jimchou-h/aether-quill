## Context

章节已有 `ChapterRecord`、`PersistedProjectState` 与 Prisma `Chapter`，尚无锁定状态。Web 的 `pages/Chapters.vue` 用本地 `ref<ChapterItem[]>` 从 workspace 取得章节，列表侧栏与当前章节详情均在 `components/chapters/ChapterList.vue`。API 在配置数据库时使用 PG 主存，未配置时保留 JSON 存储路径。章节保存和优化应用共用正文数据，优化会话使用 `updatedAt` 检查正文版本。

进行中的其他 change 和工作区未提交改动与本需求并存，本变更只增加章节标记。规格与任务在本 change 维护；历史 AQ 表仅保留索引。

## Goals / Non-Goals

**Goals:**
- 单章可锁定、解锁，列表与当前章节标题可识别状态。
- 状态按项目持久保存，兼容历史数据，遵循现有项目成员权限。
- 切换标记不修改正文或干扰已生成候选稿的版本校验。

**Non-Goals:**
- 正文保护、批量操作、原因与历史、模型或 Prompt 改动。

## Decisions

### 1. 使用独立布尔字段

增加 `isLocked`，Prisma 映射 `is_locked Boolean @default(false)`。内存记录和持久化类型同步扩展，旧 JSON 读取时以 `false` 补齐，PG 迁移为存量行提供默认值。字段不寄存在结构化解析 JSON 中，避免重新解析覆盖作者标记；不只保存在浏览器，保证刷新和不同会话读取一致。

所有章节创建路径须给出默认值；保留现有记录的更新路径须保留标记。`workspace-pg-sync.ts` 的 `buildChapterRow`、单章 upsert、全量同步和 PG 加载均映射新字段，避免后续正文保存或全量同步丢失状态。项目 JSON 备份/恢复与章节列表读取保持同一字段语义；TXT 导出仍输出正文。

### 2. 独立 PATCH 只修改标记

拟定 `PATCH /api/projects/{id}/knowledge/chapters/{chapterNo}/lock`，请求体为 `{ isLocked: boolean }`，响应为现有 envelope 包装的 `ChapterItem`，带最终 `isLocked`。先补 `openapi/openapi.yaml` 的 schema 和 path 引用及相应 path 文件，再生成共享类型、实现客户端与服务端。

复用 JWT 与 `owner/editor` 检查，验证正整数字号、严格布尔值和章节存在；viewer 仍可读取。使用目标值而非 toggle 请求，便于重复提交时保持幂等。

不复用正文 upsert，避免要求客户端回传整章、覆盖未保存正文、触发摘要或索引。单独切换标记不修改章节正文版本 `updatedAt`，不运行保存后处理，不向 orchestrator 同步该标记。服务端等待持久化完成后返回成功；沿用现有串行持久化机制，失败时恢复一致状态，保证失败请求不会在后续读取或保存时悄悄生效。实现时优先只更新锁字段，避免全记录覆盖并发正文修改。

### 3. 在现有章节页面放置轻量操作

列表标题旁与当前章节标题旁使用已有图标库的锁图标，并附「已锁定」可访问提示。已保存的当前章节在操作区提供「锁定／解锁」按钮，服务端复用现有写权限校验；空列表或尚未保存的章节不提供锁定。

沿用现有数据流：`ChapterList.vue` 发出锁定切换事件，`Chapters.vue` 调用客户端，成功后仅更新页面章节数组中目标记录的 `isLocked`，不以 PATCH 返回的整章记录替换编辑器草稿。请求期间禁用重复点击，成功后更新标识，失败通过现有错误提示恢复可操作状态。保持按钮与标识随项目和章节切换正确归属；不为单个标记新增 store。

现有章节页及客户端没有成员角色或 `canEdit` 读取链，原有编辑、删除按钮亦统一由服务端鉴权。本次沿用此交互：viewer 可读标记，修改请求由 API 拒绝，界面显示既有错误反馈；不为标记单独新增成员能力接口或改造其他操作权限。

### 4. 一个完整竖切任务

本功能规模小，绑定 `AQ-396`，一个 task 对应一个执行 issue。自动化验证先于实现，逐个行为红→绿：合法切换及权限/参数、持久化与默认值、正文保存/应用保留、UI 状态和失败反馈。复用 API、PG 映射与 Web 测试设施；界面图标位置补充轻量人工或现有浏览器 smoke 验证，不调用真实模型。

## Risks / Trade-offs

- [「锁定」可能被理解为禁止编辑] → 作者已于 2026-11-15 明确确认纯标记，正文仍可编辑；若以后需要保护正文，先修订规格。
- [新增字段在 PG 映射、JSON 恢复或覆盖导入中丢失] → 覆盖默认值、单章和全量读写、正文保存/应用保留的回归。
- [标记修改意外影响候选稿版本] → 单独更新元数据并断言 `updatedAt` 不变。
- [切章/切项目期间异步响应更新错误章节] → 请求捕获项目 ID 与章号，仅更新对应页面章节记录，不覆盖当前正文草稿。

## Migration Plan

1. 先更新 API 合同及类型，新增带默认值的非破坏性 Prisma 迁移；不改运行中业务数据文件。
2. 部署顺序为数据库迁移、API、Web；旧客户端可忽略新响应字段，新客户端读取旧数据时按未锁定展示。
3. 回滚 Web/API 时保留新列即可，正文与摘要不受影响；无需为了回滚删除已保存的标记。
