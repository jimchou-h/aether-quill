## Context

项目已有按权限读取章节、人物与角色卡的 API，生成链路也能使用项目当前生效的 `systemPromptText`。但现有模型请求只接收 system/user 文本，没有原生工具调用；项目中也没有通用聊天会话表。按场成稿使用全屏 Modal，普通页面层级上的悬浮按钮会被遮住。

## Goals / Non-Goals

**Goals:** 作者在任一项目内页面都能就指定章节连续提问；回答依据当次读取的该章正文与相关角色卡，使用该项目生效主 Prompt；聊天收起、切页和同浏览器刷新后可继续，并可在按场成稿期间打开和复制。

**Non-Goals:** 跨设备同步、任意章节的自主搜索规划、模型原生工具调用、自动改稿、持久化作者偏好、在聊天中编辑项目 Prompt。

## Decisions

### 1. 服务端决定读取材料，模型负责回答

新增项目级只读聊天 SSE 接口。API 先校验用户对项目的访问权，再从本轮问题识别明确的“第 N 章”（支持常见阿拉伯数字和中文数字）；无明确章号时沿用本会话传入的当前章节。首次没有章节锚点时直接提示指定章节。章节不存在时返回明确错误，不调用模型。

服务端读取该章**最新完整正文**，按现有出场人物/角色卡关联规则选取本项目相关卡片，并将两者明确加入本轮模型输入；不以摘要、结构化文本或向量命中代替正文。正文更新后下一轮重新读取。普通约一万字章节不得套用按场成稿的短范围限制；确实超出本次模型输入预算时，才明确提示作者缩小范围，不静默截断。第一版不读取整本书或自动推断任意跨章问题。

备选方案是扩展 Provider Adapter 做通用 tool calling；现阶段只需“指定章或当前章”的读取，增加模型工具循环会扩大接口和测试面，暂不采用。

### 2. 项目主 Prompt 保持主导

每轮解析当前项目**已发布、生效**的主 Prompt，作为现有 system 消息的项目层；另加简短、版本化的编辑问答任务说明，限定引用原文、区分事实与建议、默认不改稿。任务说明不复制或覆盖项目主 Prompt。会话历史与读取材料放入 user 上下文，并设置长度预算；服务端不把客户端提交的历史提升为 system 指令。使用项目当前写作模型配置，沿用现有生成与 SSE 基础设施。

### 3. 第一版记忆留在当前浏览器

第一版每个 `userId + projectId` 只有一段当前聊天。Web 端增加 `idb` 直接依赖，用 IndexedDB 按此复合身份保存 user/assistant 消息和当前章号，不保存章节正文或角色卡全文；收起、项目内路由切换与刷新后恢复。已保存历史可在界面查看；请求只携带有界的最近对话，服务端限制条数与长度。切换账号或项目时加载独立会话。存储的历史用于接续“刚才第二条”等追问，章节事实始终以服务端当次读取为准。

面板提供“清空当前聊天”：若正在生成，先中止该请求，再通过 `idb` 删除当前 `userId + projectId` 的会话记录并重置内存中的消息与当前章号；其他用户、项目的记录和项目资料不变。完成中的旧响应不得重新写回已清空的会话。

备选方案是 `localStorage` 或新增服务端会话表；IndexedDB 能保存较长的本地聊天历史，`idb` 使异步读写保持简洁，且无需服务端迁移。模型上下文仍只取近期对话，不等于把全部已保存历史发送给模型。清除浏览器数据或换设备后历史不会恢复，界面应明确这一点。

### 4. 项目级面板独立于按场成稿弹窗

聊天状态与悬浮入口挂在项目共享页面；面板 Teleport 到顶层并高于全屏按场 Modal。按场 Modal 内提供打开**同一面板**的入口，避免遮罩和焦点捕获导致悬浮按钮不可用。聊天展开、收起只变更聊天状态，不关闭或重建按场 Modal。每条助手回答提供复制按钮；关闭聊天后焦点回到触发位置。

## Risks / Trade-offs

- **章号识别范围有限** → 第一版只承诺明确章号和当前章追问；无法定位时提示作者指定，不猜章节。
- **角色卡关联不完整** → 只注入确能与本章人物匹配的现有卡片；不编造缺失资料。
- **长章或长历史超预算** → 对历史设上限；正文超限时明确反馈，不默默用摘要替代。
- **全屏 Modal 的层级、Tab 与 Esc 冲突** → 用顶层面板和按场弹窗内入口，并做一次真实 UI 操作验收。
- **本地记忆不跨设备** → 在界面说明边界；后续确有需要再增加服务端持久化。

## Migration Plan

先定义 OpenAPI 合同，再加入只读接口、版本化任务说明、Web 端 `idb` 依赖和项目级面板。首版没有旧聊天数据要迁移；回滚时移除入口及新接口即可，现有章节和按场成稿数据不变。

## Open Questions

无阻塞项。首版以明确章号和同浏览器近期对话为验收范围。
