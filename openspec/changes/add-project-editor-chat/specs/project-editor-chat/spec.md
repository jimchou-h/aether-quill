## ADDED Requirements

### Requirement: 作者能在当前项目内询问指定章节

系统 MUST 为有项目访问权的作者提供只读编辑聊天。用户明确提到“第 N 章”时，服务端 MUST 读取该项目该章的最新正文及能匹配的相关角色卡，并使用该项目当前生效的主 Prompt 回答；不得只用章节摘要或结构化信息冒充正文。首次提问没有可确定的章节时，系统 MUST 提示用户指定章节，不得猜测。

#### Scenario: 指定章节提出优化问题

- **WHEN** 作者在项目 A 问“第 7 章有什么优化想法”，且第 7 章存在
- **THEN** 系统 MUST 根据项目 A 的第 7 章最新正文和可匹配角色卡生成建议
- **AND** 系统 MUST 使用项目 A 当前生效的主 Prompt，不读取项目 B 的材料

#### Scenario: 原文不足或角色卡缺失

- **WHEN** 问题所需的事实在第 7 章和已匹配角色卡中未交代
- **THEN** 回答 MUST 区分已知内容与建议，不得把未交代的设定说成事实

#### Scenario: 无章号且无当前章

- **WHEN** 新会话中的问题没有可识别的章号，也没有已讨论的当前章
- **THEN** 系统 MUST 提示作者指定章节，不得任意选一章回答

#### Scenario: 项目无权或章节不存在

- **WHEN** 用户无权访问目标项目，或所指章节在当前项目不存在
- **THEN** 系统 MUST 按现有权限或缺失资源语义拒绝，不得向模型发送该项目的章节或角色卡内容

### Requirement: 建议有原文依据且不自动改稿

针对正文具体位置提出的优化建议 MUST 引用可定位的本章原文短句，并说明拟改方向；聊天回答 MUST NOT 修改章节正文、角色卡或项目 Prompt。作者可复制回答自行使用。

#### Scenario: 得到可追溯建议

- **WHEN** 作者询问某章有哪些值得优化的地方
- **THEN** 回答 MUST 将具体建议与该章的原文位置关联，并解释建议希望改善的阅读效果

#### Scenario: 对话只提供建议

- **WHEN** 作者收到建议或点击复制回答
- **THEN** 章节、角色卡和项目 Prompt MUST 保持原状

### Requirement: 同浏览器内按用户和项目保留近期对话

系统 MUST 在当前浏览器通过 `idb` 使用 IndexedDB，按用户与项目分别保留当前聊天历史和当前章号，不得在该存储中保存章节正文或角色卡全文。没有新章号的追问 MUST 沿用该会话当前章；每轮涉及章节事实时 MUST 重新读取当前正文。发送给模型的历史 MUST 有条数与长度上限，并作为对话数据而非高优先级指令。

#### Scenario: 追问及刷新后续聊

- **WHEN** 作者在项目 A 问第 7 章的优化建议，随后问“刚才第二条怎么改”，并收起面板或刷新页面
- **THEN** 系统 MUST 恢复该浏览器中项目 A 的近期对话与当前章号，追问仍指向第 7 章

#### Scenario: 正文已被修改

- **WHEN** 作者修改并保存第 7 章后继续讨论该章
- **THEN** 本轮引用的章节事实 MUST 来自修改后的正文，不得仅沿用旧聊天内容

#### Scenario: 切换项目或账号

- **WHEN** 作者从项目 A 切到项目 B，或在同一浏览器切换账号
- **THEN** 聊天 MUST 切换到对应用户与项目的独立历史、当前章和主 Prompt，不得显示其他组合的记录

#### Scenario: 清空当前聊天

- **WHEN** 作者点击“清空当前聊天”，包括在回复生成过程中点击
- **THEN** 系统 MUST 中止本次生成，并清除当前用户、当前项目的消息与当前章号
- **AND** 已清空的旧回复 MUST NOT 再写回聊天；其他用户和项目的记录、章节、角色卡与 Prompt MUST 保持不变

### Requirement: 项目全局聊天面板可与按场成稿并用

系统 MUST 在项目内页面提供可展开、收起的聊天入口和可复制的助手回答。按场成稿全屏弹窗打开时，作者 MUST 仍能打开同一聊天面板、复制回答再收起；这些操作 MUST NOT 关闭、重置或改写按场成稿中的选区、方案或草稿状态。

#### Scenario: 项目页面展开与收起

- **WHEN** 作者在项目内页面打开聊天、发送问题后收起，再进入另一个项目内页面重新打开
- **THEN** 面板 MUST 保留当前会话内容，并能继续发送消息

#### Scenario: 按场成稿期间复制建议

- **WHEN** 按场成稿全屏弹窗已打开且含未提交的选区或方案
- **THEN** 作者 MUST 能在其上方打开聊天、复制一条回答并收起
- **AND** 原按场成稿弹窗的选区和方案 MUST 保持不变

#### Scenario: 生成失败

- **WHEN** 聊天生成请求失败或流式响应中断
- **THEN** 面板 MUST 呈现可理解的错误，已保存的近期对话 MUST 仍可查看
