## Why

作者目前要把章节复制到别处，才能就某一章的优化想法连续提问；建议也难以带回按场成稿。项目已有章节、角色卡和主 Prompt，适合提供一个始终可打开的项目内编辑对话。

## What Changes

- 在项目页面提供可展开、收起的聊天面板；按场成稿全屏弹窗打开时也能使用、复制回答，关闭聊天不重置按场成稿。
- 作者询问指定章节或继续追问时，服务端在当前项目内读取该章正文及相关角色卡，使用该项目当前生效的主 Prompt 生成有原文依据的优化建议。
- 通过 `idb` 将会话与当前讨论章节保存在当前浏览器的 IndexedDB，按用户、项目隔离；收起、切换项目内页面或刷新后仍可续聊，并可清空当前聊天。章节事实以当次读取的现有正文为准。
- 第一版只提供只读建议和复制，不自动修改章节、角色卡或 Prompt；不建设通用模型工具调用框架。

## Capabilities

### New Capabilities

- `project-editor-chat`: 项目内章节编辑对话、资料读取、多轮记忆及全局面板。

### Modified Capabilities

- `chapter-ai-surface`: 允许项目级编辑聊天入口出现在章节页面及按场成稿期间，不改变既有文笔优化与按场成稿入口范围。

## Impact

涉及项目级前端布局与弹层、Web 端 `idb` 依赖及 IndexedDB 会话状态、API 权限校验、章节与角色卡读取、生成编排和项目主 Prompt 传递。需先新增 OpenAPI 聊天接口合同；缺失章节与无权限优先复用现有错误码，不计划新增错误码、服务端数据库表或模型供应商依赖。

## Non-goals

不做自动改稿、跨项目检索、跨设备聊天同步、自动写入长期人物设定、整书自由探索、聊天质量的多轮自动评测或新的通用 Agent 平台。
