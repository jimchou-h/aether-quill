## Context

文笔优化方案改写现为：要求 → 方案 SSE → 用户确认 → 正文 SSE → 应用。直接改写已跳过方案。长章方案含 segment_diagnosis；from-plan 正文目前整章单次生成。

## Goals / Non-Goals

**Goals**

- 方案与正文各自 1～3 轮连跑；后一轮吃前一轮结果。
- 可选：全部方案轮次结束后自动开写正文。
- 失败/中断保留上一轮成功稿；应用仍确认。

**Non-Goals**

- 直接改写、创作精修、终稿合规、工作台续写。
- 服务端一次请求跑完 N 轮。
- 项目 Settings 持久化（仅浏览器 localStorage）。

## Decisions

1. 正文第 2 轮起 `sourceText` = 上一稿，校验仍对入库原文。
2. 自动开写：方案全结束后立刻写正文；过程中方案只读；结束后可返回方案。
3. 正文收紧：同一 draft 模板，有 `sourceText` 时追加不得另起方案的硬约束。
4. 方案第 2 轮：复用 revision 接口 + 固定收紧意见，不重新诊断。
5. 次数与自动开写分控件，浏览器记住。
6. 前端连续打现有 plan/draft SSE。

## Risks / Trade-offs

- 2～3 轮整章生成耗时长、费用高；默认仍为 1，记住上次可能造成意外连跑。
- 第 2 轮蓝本是上一稿，字数闸门仍对入库原文，可能因过短失败。
